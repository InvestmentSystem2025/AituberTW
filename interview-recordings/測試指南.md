## 📝 測試步驟

### 步驟 1：啟用錄製功能

**在 VSCode PowerShell 終端執行**：
```powershell
npm run dev
```

1. 訪問：`http://localhost:3000/interview`
2. **重要**：打開瀏覽器的開發者工具（F12）查看 Console
3. 在人臉檢測頁面，點擊左上角「面試設置」按鈕
4. 在設置彈窗中，啟用「🎥 錄製面試過程」開關（應該變紅色）
5. 點擊「保存設置」

**預期 Console 輸出**：
```
✅ 設定已保存並通知: {enablePersonDetection: true, enableRecording: true}
📝 錄製設定已更新: true
```

### 步驟 2：開始面試並確認錄製啟動

1. 進行人臉檢測或點擊「開始面試」按鈕
2. 面試開始後，查看 Console

**預期 Console 輸出**：
```
🎥 檢查錄製設定: {enableRecording: true}
🎬 準備開始錄製...
🎬 開始準備錄製面試...
```

3. **關鍵步驟**：瀏覽器會彈出螢幕分享權限請求
   - 選擇「整個螢幕」或「視窗」或「Chrome 分頁」
   - 選擇當前的面試分頁
   - 勾選「同時分享音訊」（如果可用）
   - 點擊「分享」

**預期 Console 輸出**：
```
✅ 螢幕錄製權限獲取成功
✅ 麥克風音頻獲取成功
🎥 使用編碼: video/webm;codecs=vp9,opus
✅ 錄製已開始
```

4. 在輸入框上方應該會看到紅色的「● 錄製中」指示器

### 步驟 3：進行面試

1. 正常進行面試對話
2. 錄製指示器應該一直顯示

**預期 Console 輸出（每 10 秒）**：
```
📦 錄製數據片段: XXXXX bytes
```

### 步驟 4：結束面試並下載錄製

1. 點擊「結束面試」按鈕
2. 等待面試結果頁面出現

**預期 Console 輸出**：
```
🛑 停止錄製...
🛑 錄製停止，開始處理檔案...
📊 錄製檔案大小: XX.XX MB
✅ 錄製檔案已下載: interview_recording_2025-10-01T14-30-00-000Z.webm
```

3. 瀏覽器會自動下載錄製檔案到預設下載資料夾
4. 檔案名稱格式：`interview_recording_YYYY-MM-DDTHH-MM-SS-SSSZ.webm`

## 🐛 常見問題排查

### 問題 1：沒有出現螢幕分享權限請求

**可能原因**：
- 錄製設定沒有正確保存
- enableRecording 狀態沒有更新

**檢查方法**：
1. 打開 Console，搜尋「錄製設定」
2. 應該看到 `📝 錄製設定已更新: true`
3. 在面試開始時應該看到 `🎥 檢查錄製設定: {enableRecording: true}`

**解決方法**：
1. 重新打開面試設置
2. 確認「🎥 錄製面試過程」開關是紅色（啟用狀態）
3. 再次點擊「保存設置」
4. 重新開始面試

### 問題 2：看到錯誤訊息

**檢查 Console 錯誤**：
- `❌ 開始錄製失敗`: 權限被拒絕或瀏覽器不支援
- `⚠️ 無法獲取麥克風音頻`: 麥克風權限被拒絕（影響不大）

**解決方法**：
1. 確認使用 Chrome/Edge 瀏覽器（Firefox 可能有兼容問題）
2. 確認網站有螢幕錄製權限
3. 在瀏覽器設定中檢查權限設定

### 問題 3：錄製檔案沒有自動下載

**可能原因**：
- 瀏覽器阻擋了下載
- 沒有錄製到任何數據

**檢查方法**：
1. 查看 Console 是否有「錄製數據片段」訊息
2. 查看瀏覽器下載欄是否被阻擋

**解決方法**：
1. 允許網站自動下載檔案
2. 確保面試時長至少有 10 秒以上

## 🎬 播放錄製檔案

### 支援的播放器：
- **VLC Media Player** （推薦）
- **Windows Media Player**（需要安裝 codec）
- **Chrome 瀏覽器**（直接拖放檔案）
- **PotPlayer**

### 轉換為 MP4（可選）：

**在 PowerShell 中執行**（需要安裝 FFmpeg）：
```powershell
ffmpeg -i input.webm -c:v libx264 -c:a aac -strict experimental output.mp4
```
