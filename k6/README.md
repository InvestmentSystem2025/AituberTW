# k6 load testing (staging)

This folder contains small k6 scripts intended for **staging**.

## Prerequisites

- k6 installed on your machine/runner
- Staging is protected by Caddy Basic Auth (frontend only)

## Quick start

```bash
k6 run ^
  -e BASE_URL=https://stg.ai-interview.tw ^
  -e BASIC_USER=stg ^
  -e BASIC_PASS=YOUR_PASSWORD ^
  k6/stg_http_smoke.js
```

Notes:

- If you use a hashed password in Caddy (`BASIC_AUTH_PASS_HASH`), k6 still needs the **plaintext** password for the `Authorization: Basic ...` header.
- If you later decide to protect only certain routes, adjust the script accordingly.

## Interview API load test (seed + API-only)

- Script: `k6/interview-api-load.js`
- Accounts file: `tmp/stress-accounts.json` (generated by `node scripts/seed-stress-users.mjs`)
- Detailed guide (Traditional Chinese): `docs/interview-load-testing_zh-TW.md`
- **Server-side metrics** (CPU, memory, load average): k6 only reports client-side metrics. To see VM resource usage during the test, run `scripts/vm-stats-during-load.sh` on the **target VM** while k6 runs, or use GCP Console monitoring. See doc section 「2.5) 伺服器端負荷」.
